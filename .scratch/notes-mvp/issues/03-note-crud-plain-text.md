# 03 — Create, edit, delete, and list Notes (plain text)

**What to build:** The "All Notes" list screen (flat, sorted by most-recently-edited), a "+ New Note" action that creates a blank Note and opens it for editing, continuous autosave of edits through the Notes repository, a derived title (first line of content) shown in the list, deleting a Note behind a "this can't be undone" confirmation prompt, and silent discard of a Note that was created but never had any content typed into it before the user navigated away. Uses a plain multiline text input for content at this stage, not rich text — this ticket proves the full CRUD loop end-to-end before formatting is layered on top in the next ticket.

**Blocked by:** 01, 02

**Status:** done

- [x] "All Notes" list shows every Note, sorted by most-recently-edited, each row showing its derived title
- [x] Tapping "+ New Note" creates a blank Note and opens it for editing
- [x] Edits autosave continuously via the Notes repository — no explicit save action exists
- [x] Deleting a Note shows a confirmation prompt; only on confirming does the repository's delete run
- [x] A Note created but left with no content, when navigated away from, is never persisted and never appears in the list
- [x] Reopening an existing Note loads its current content and continues to autosave edits

## Comments

Implemented across `app/index.tsx` (All Notes), `app/note/[id].tsx` (editor), `db/context.tsx` (repository wiring), and `lib/notes/autosave.ts` (the create/update/delete/discard decision logic), commit range starting at this ticket.

- Replaced the Expo template's tab navigation and demo screens (`app/(tabs)/`, `app/modal.tsx`, `HelloWave`/`ParallaxScrollView`/`Collapsible`/`ExternalLink`/`HapticTab` and their unused assets) with the app's real navigation: a root `Stack` with `index` ("All Notes") and `note/[id]` (the editor). Folders (ticket 05) will likely reshape this further, but there was no reason to keep the starter's placeholder screens around in the meantime — see AGENTS.md's note that Expo has changed; this repo's `app/` now only contains real screens.
- `db/context.tsx`'s `DatabaseProvider` opens the database and runs migrations once at app startup (wrapping `db/client.ts`'s `openDatabase`/`runMigrations` from ticket 02), exposing the resulting repository via `useNotesRepository()`. Renders a spinner while migrating and an error screen if opening the database fails outright, so no screen underneath ever renders against a repository that isn't there yet.
- **The create/update/delete-on-empty decision is a pure, unit-tested seam** (`lib/notes/autosave.ts`'s `decideAutosave`/`decideOnLeave`), independent of React and the repository — the editor screen is a thin consumer that executes whatever action they return. A Note only starts existing in the repository once it has real (non-blank) content; mid-edit, further changes update it in place. On navigating away, a Note left with no content is removed — whether it was never persisted (nothing to do) or was persisted earlier in the session and typed back down to nothing (deleted) — which is a small extension beyond the ticket's literal "never had any content typed into it" wording, applied for consistency with Apple Notes-style behavior the domain vocabulary in `CONTEXT.md` is modeled on.
- Autosave is debounced (400ms) rather than firing on every keystroke, and repository writes for a given Note are serialized through a promise chain (`enqueueSave`) rather than fired independently — otherwise a debounced `updateNoteContent` could run before the `createNote` it depends on had resolved. The leave-time decision (`decideOnLeave`) is deferred until it actually executes in that same chain, not computed eagerly before enqueueing — an earlier version computed it eagerly and a 3-angle-convergent `/code-review` finding caught the resulting race: navigating away right after the debounce fired but before its `createNote` resolved could read a stale `noteId` and enqueue a second `createNote` for the same content (or, symmetrically, fail to clean up a note that got emptied out while its create was still in flight). Fixed by moving the decision inside the queued closure so it only runs after every previously-chained write (including any pending create) has actually completed.
- The list screen (`app/index.tsx`) re-fetches on every focus (`useFocusEffect`) rather than holding any live subscription — it has no way to otherwise learn about a note that autosaved, got created, or got discarded on the previous screen. Both `listNotes` and `deleteNote` now handle rejections explicitly (log + no-op for the list refresh; log + a user-facing alert for a failed delete) rather than leaving unhandled promise rejections.
- Consolidated three ad hoc gray hex pairs (a placeholder color, a list separator color, and — already existing — the theme's `icon` color) that had drifted into inline overrides at different call sites into two new tokens on `constants/theme.ts`'s `Colors` (`separator`, `placeholder`), and factored the loading spinner that both `db/context.tsx` and the editor screen needed into a shared `components/loading-view.tsx`.
- Test suite: `lib/notes/__tests__/autosave.test.ts` (8 cases covering every branch of `decideAutosave`/`decideOnLeave`, including the blank-vs-persisted matrix). Screens themselves aren't unit-tested — there's no React Native component-testing library set up in this repo yet, and per the "thin consumer" seam design, the decision logic that actually needed coverage lives in the pure functions the screens call. 42/42 tests passing across the full suite (incl. ticket 02's); `tsc --noEmit` and `eslint` both clean.
- Ran `/code-review` (9 parallel angles) against the diff before committing. The duplicate-create/orphaned-note race above was independently found by three separate angles (cross-file tracer, line-by-line scan, domain-rule scan) and fixed. Also fixed: a stuck loading spinner if `getNote` ever rejected (now shows an error state) or if the route's `id` param were ever non-numeric (now treated as not-found rather than querying with `NaN`); `decideOnLeave`'s non-blank branch, which was a byte-for-byte duplicate of `decideAutosave`, now delegates to it. Deliberately deferred (noted, not fixed, as out of scope for this ticket): migrating the list screen to `drizzle-orm`'s `useLiveQuery` instead of focus-based polling; extracting the debounce/promise-chain machinery into a generic reusable primitive (currently has exactly one call site); a TOCTOU gap in `createNote`/`moveNote`'s folder-existence check (unreachable today with no folder UI yet — ticket 05); and `FlatList` row re-render memoization (not worth it at this list size).
